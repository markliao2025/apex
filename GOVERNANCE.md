# Governance

Apex uses a lightweight maintainer model during Phase 0.

## Decisions

- Product and safety boundaries are recorded in the main product plan.
- Architecture or risk-semantic changes require an ADR under `docs/architecture/`.
- Routine implementation decisions use normal pull-request review.
- Maintainers publish unresolved tradeoffs rather than silently changing risk meaning.

## Roles

- Maintainers merge changes, publish releases, moderate community spaces, and handle
  security reports.
- Contributors may propose code, fixtures, adapters, documentation, and test vectors.
- Domain reviewers may approve astrodynamics claims without becoming maintainers.

## Changes to governance

Material governance changes require a public RFC and at least seven calendar days for
comment once the repository has an active community.
