# Build in Public validation

Phase 0 uses public artifacts and observable behavior as an interview
alternative. It is not a substitute for evidence: impressions, likes and raw
traffic are not counted as successful workflows.

## Weekly cadence

1. Ship one narrow, runnable change.
2. Publish a 60–90 second unedited workflow recording.
3. Ask one decision-focused question.
4. Link to the exact tagged version and Quickstart.
5. Record attempts, completion, time-to-value, errors and qualitative feedback.
6. Publish what will be kept, changed or removed next week.

Suggested weekly questions:

- Could you explain why this event needs attention from the evidence shown?
- Which missing datum prevents a real decision?
- Does the planning-impact comparison reflect a workflow you already perform?
- What would make you distrust this result?
- Which export would you actually share with a colleague?
- What should be removed before anything else is added?

## Evidence rules

- Count a completed workflow only when the user reaches replay output and can
  explain the provided-Pc/covariance warning.
- Separate repository visitors, demo starts and completed workflows.
- Do not store email, operational CDM, credentials or restricted source data in
  the public log.
- Use synthetic, public, or explicitly shareable events only.
- Record failed setup attempts and timeouts; do not quietly drop them.
- Link qualitative quotes only with permission and remove identifying details.
